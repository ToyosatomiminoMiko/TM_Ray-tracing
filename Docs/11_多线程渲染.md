# 多线程渲染

## 为什么渲染适合多线程

光线追踪里,一个像素的颜色只由"穿过这个像素的光线"决定,
不依赖旁边像素的结果.整张图可以看成 \( W \times H \) 个互相独立的小任务:

$$
\text{像素}(i,j) \rightarrow \text{只读场景} \rightarrow \text{输出颜色}
$$

这种"每个任务都独立、任务之间不通信"的并行叫**数据并行**,
也是渲染能简单加速的原因:把画面切成几块,每个线程负责一块.

## 最简单的切法:按行带切

Lesson10 把屏幕从中间分成左右两半:

- 左半:一个线程从头到尾渲染,得到单线程基准时间;
- 右半:切成 `N` 条水平行带,`N` 个线程同时渲染;
- 两边使用完全相同的场景和 2x2 超采样,只是任务分配方式不同.

用行而不是列,是因为:

1. 每行代码是同一个循环,切分逻辑最简单;
2. 连续行更容易命中 CPU 缓存;
3. 行数(900)远大于线程数(通常 4~16),总能均匀切分.

核心数据结构只有一个"工作块":

```c
typedef struct
{
    framebuffer_t *fb;
    int x0, x1;  /* 这块负责哪些列 */
    int y0, y1;  /* 这块负责哪些行 */
    mat4 view_t; /* 场景参数,所有线程只读 */
} render_job_t;
```

主线程把行带分好后,每个线程执行同一个入口函数:

```c
static void *render_rows(void *arg)
{
    render_job_t *job = (render_job_t *)arg;
    for (int j = job->y0; j < job->y1; j++)
        for (int i = job->x0; i < job->x1; i++)
            /* 对像素 (i,j) 着色并写回帧缓冲 */
    return NULL;
}
```

## 为什么不需要加锁

多个线程同时写内存,只有在"写同一个地址"时才会冲突.
Lesson10 里线程 `t` 只写行 `[y0, y1)`,不同线程的行范围不重叠,
所以每个像素只有一个写者,不需要互斥锁.

同理,场景表、光源、相机矩阵都是只读数据,所有线程可以安全共享.
如果渲染函数里用了会修改的全局变量(例如统计计数),那就要加锁,
或者改成"每个线程一份私有数据,最后再合并".

## 怎么量时间

计时要用墙钟时间 `clock_gettime(CLOCK_MONOTONIC)`,
不要用 `clock()`:

- 墙钟:真实过去的时间,多线程并行时 4 个线程同时干活,墙钟明显变短;
- `clock()`:返回进程累计消耗的 CPU 时间,4 个线程各跑 1 秒会显示 4 秒,
  看起来反而更慢.

运行 Lesson10 时终端会打印:

```text
[lesson10] 左半单线程 1240.00 ms | 右半 16 线程 133.00 ms | 加速 9.3x
```

## 实验:不同线程数

课程支持环境变量 `RAY_THREADS`,可以不改代码反复实验:

```sh
RAY_THREADS=1 ./ray.sh lesson10 ppm
RAY_THREADS=2 ./ray.sh lesson10 ppm
RAY_THREADS=8 ./ray.sh lesson10 ppm
```

线程数从 1 加到核数时,耗时一般会明显下降;超过核数后
提升会变小,因为 CPU 已经在满负荷运转,再多线程只会增加调度开销.

## 加速比与 Amdahl 定律

假设单线程耗时 \( T_1 \),多线程耗时 \( T_n \),加速比定义为:

$$
S_n = \frac{T_1}{T_n}
$$

理想情况下 \( S_n = n \),实际会低于 \( n \),
因为有线程创建/回收、内存带宽、任务不均衡等开销.
Amdahl 定律给出了上限:如果程序里有比例 \( p \) 的部分可以并行,
其余 \( 1-p \) 必须串行,那么:

$$
S_n \le \frac{1}{(1-p) + \frac{p}{n}}
$$

渲染循环本身几乎全部可并行,所以接近线性加速;
但每一帧之前都要清屏、之后要输出文件,这些串行部分决定了最终上限.

## 真实渲染器会怎么做

Lesson10 为了教学,每次渲染都现场创建线程.生产环境通常:

1. **线程池**:启动时创建固定数量的线程,反复复用,避免每次创建/销毁的开销;
2. **动态取任务**:不把行带一次分死,而是维护一个"待渲染行队列",
   谁空闲谁取下一行,负载更均衡;
3. **多级并行**:除了像素并行,还可以对反射/折射递归、光照采样做并行;
4. **注意缓存**:相邻线程尽量处理相邻行,减少互相挤占缓存;
5. **确定性**:多线程下任务完成顺序不确定,如果动画需要逐帧一致,
   可以用固定随机种子或按像素独立采样,避免画面闪烁.
