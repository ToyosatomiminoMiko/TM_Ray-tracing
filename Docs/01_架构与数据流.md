# 架构与数据流

## 分层结构

```
main.c            命令入口:选课、控制输出模式
  |
  +-- Lessons/    每节课一个目录,只负责"画什么"
  |     registry.c  课程注册表(新增课程只改这里)
  |
  +-- Core/
        math/      vec3、mat4:纯数学函数,带公式注释
        render/    framebuffer:内存帧缓冲;output:终端/PPM 输出
        raytrace/  ray、sphere、triangle、plane:求交纯函数

Docs/             理论 + 方法文档
```

## 核心约定:统一先渲染到内存

旧版本里,终端动画直接读内存缓冲,而光照示例直接用 `fprintf` 写 PPM 文件,
导致"同一份场景"有两种不同的输出路径。

重构后的约定只有一条:

> 课程代码只能往 `framebuffer_t`(内存)里画像素,不允许直接写文件。

数据流:

```
课程渲染函数 -> 内存帧缓冲 framebuffer_t
                     |
                     +--> output_ansi() 终端动画(逐帧清屏)
                     +--> output_ppm()  PPM 文件(P3 文本)
```

这样做的优点:

1. 场景代码与输出方式解耦,同一帧可以既看终端又存文件;
2. 动画课程可以无改动地导出成 PPM 序列,再合成 GIF/视频;
3. 课程代码更短,学习者只关注"往像素里填颜色"。

## 纯函数约定

数学模块(向量、矩阵、求交)全部写成纯函数:

- 不修改入参;
- 不使用全局可变状态;
- 同样的输入永远得到同样的输出。

例如 `vector3_add`、`intersect_sphere_fast` 都是纯函数。
输出函数(`output_ansi`、`output_ppm`)只读取帧缓冲,不修改它。

## 课程接口

每节课只需实现:

```c
int lessonXX_render(framebuffer_t *fb, int frame);
```

`frame` 是帧号;`frames = 0` 表示静态单帧,`frames > 0` 表示动画。
main 负责清空缓冲、循环帧、选择输出方式。
